# Project Proposal: UP Board

## 1. Theme
**Theme: Community (ชุมชนและการสื่อสารภายในมหาวิทยาลัย)**
เหตุผลคือเราต้องการสร้างพื้นที่ส่วนรวมที่เป็นระเบียบสำหรับนิสิตและบุคลากรในมหาวิทยาลัยพะเยา เพื่อแก้ปัญหาการรับส่งข่าวสารที่กระจัดกระจายและสับสนวุ่นวายบนโซเชียลมีเดีย ระบบนี้จะช่วยยกระดับการสื่อสารภายในแคมปัสให้เข้าถึงง่าย ทันสถานการณ์ และตรงกลุ่มเป้าหมายมากยิ่งขึ้น

## 2. Project name
**UP Board** (The Ultimate Campus Community Hub)

## 3. Persona หลัก
**นิสิตและบุคลากรของมหาวิทยาลัยพะเยา (Campus User):** 
ผู้ใช้งานที่ต้องการช่องทางที่รวดเร็วและเป็นระเบียบในการกระจายข่าวสารและแบ่งปันเรื่องราวในรั้วมหาวิทยาลัย ไม่ว่าจะเป็นการประชาสัมพันธ์กิจกรรม ประกาศของหาย การบอกต่อเรื่องราวดีๆ ไปจนถึงการแจ้งเหตุเร่งด่วนและงานซ่อมบำรุง พวกเขาต้องการแพลตฟอร์มที่ข้อมูลสดใหม่ ไม่ถูกอัลกอริทึมปิดกั้น และไม่ต้องการเห็นโพสต์ขยะรบกวนสายตา

## 4. Value proposition
**สำหรับ** นิสิตและบุคลากรของมหาวิทยาลัยพะเยา **ผู้ซึ่ง** ต้องการช่องทางที่รวดเร็วและเป็นระเบียบในการกระจายข่าวสาร **ผลิตภัณฑ์ของเราคือ** UP Board ซึ่งเป็นศูนย์รวมข่าวสารที่ให้พื้นที่อัปเดตข้อมูลแบบทันทีพร้อมแยกหมวดหมู่ชัดเจน 

**ไม่เหมือนกับ** กลุ่ม Facebook ที่สับสนวุ่นวาย ที่ซึ่งโพสต์ถูกมัดรวมกันและมักโดนระบบปิดกั้นการมองเห็น **ผลิตภัณฑ์ของเรา** จัดระเบียบโพสต์แยกตามหมวดหมู่ พร้อมระบบลบโพสต์อัตโนมัติใน 24 ชั่วโมง เสริมด้วยระบบปักหมุดสำหรับประกาศสำคัญ และที่สำคัญที่สุดคือ ตัวระบบจะช่วยแยกเรื่องแจ้งซ่อมส่งตรงถึงมือเจ้าหน้าที่โดยอัตโนมัติ ไม่ปล่อยให้เป็นเพียงโพสต์บ่นลอยๆ

## 5. MoSCoW priorities
*   **Must Have:** ระบบสร้างโพสต์แบบเลือกหมวดหมู่, ฟีดข้อมูลแยกตามหมวดหมู่แบบเรียลไทม์, ระบบ Backend แยกแยะและส่งต่อเรื่องแจ้งซ่อมถึงเจ้าหน้าที่, ระบบลบ/ซ่อนโพสต์อัตโนมัติ 24 ชั่วโมง
*   **Should Have:** ระบบปักหมุด (Pin) โพสต์ที่สำคัญ, ช่องค้นหา (Search Bar) ด้วยคำสำคัญ, เครื่องหมาย Verified Badge สำหรับคณะหรือสโมสร
*   **Could Have:** ปุ่ม "เจอเหมือนกัน (Me Too)" เพื่อดันโพสต์แจ้งเหตุที่มีคนเดือดร้อนจำนวนมาก
*   **Won't Have (this term):** ระบบส่งข้อความสนทนาส่วนตัว (Direct Message) ระหว่างผู้ใช้งาน

## 6. Risks & assumptions
*   **Assumptions (สมมติฐานที่ต้อง Validate):** นิสิตและบุคลากรพร้อมที่จะเปลี่ยนพฤติกรรมจากการโพสต์ปัญหาทุกอย่างลงใน Facebook กลุ่มรวม มาเป็นการใช้งานแอปพลิเคชันหรือเว็บบอร์ดของมหาวิทยาลัยที่มีการจัดหมวดหมู่แทน
*   **Risks (ความเสี่ยงที่อาจเจอ):** ผู้ใช้อาจเลือกหมวดหมู่ผิด (เช่น โพสต์เรื่องทั่วไปในหมวดแจ้งซ่อม) หรือมีการโพสต์เนื้อหาที่ไม่เหมาะสม ซึ่งอาจทำให้เจ้าหน้าที่สับสน จำเป็นต้องบรรเทาความเสี่ยง (Mitigation) ด้วยระบบให้ผู้ใช้รายงานโพสต์ (Report Post) เพื่อให้ผู้ดูแลระบบเข้ามาตรวจสอบและจัดการต่อ

## 7. AI Usage Guidance
# นโยบายการใช้ Generative AI (AI Usage Guidance)

ในการพัฒนาโปรเจกต์นี้ ทีมงานได้มีการใช้เครื่องมือ AI เป็นผู้ช่วยในการทำงาน โดยปฏิบัติตามกฎเกณฑ์ของรายวิชาอย่างเคร่งครัด ดังนี้:

- **เครื่องมือที่ใช้:** Google Gemini
- **สิ่งที่ใช้ AI ช่วยทำ :**
  1. **Brainstorm features:** ใช้ AI ช่วยระดมสมองคิดฟีเจอร์ต่างๆ จาก Persona ที่ทีมเป็นคนกำหนดเอง
  2. **เขียน Acceptance Criteria:** ใช้ AI ช่วยจัดโครงสร้างและร่าง Acceptance Criteria จาก User Story ทุกข้อ เพื่อให้อ่านง่ายและครอบคลุม
  3. **Estimate effort:** ใช้ AI ช่วยประเมินขนาดงานเบื้องต้น (Size S/M/L) 
- **กระบวนการตรวจสอบโดยมนุษย์ (Verification):**
  - **ทีมเป็นผู้ตัดสินใจหลัก:** การเลือก Theme, การกำหนด Persona และการตัดสินใจเลือกว่าจะทำฟีเจอร์ไหน ทีมเป็นคนเคาะและตัดสินใจด้วยตัวเองทั้งหมด (ไม่ได้ให้ AI คิดแทน)
  - **การตรวจทาน (Review):** สมาชิกในทีมได้อ่านทบทวนผลลัพธ์จาก AI ทุกครั้ง และได้ทำการปรับแก้เนื้อหาให้สอดคล้อง (Align) กับเป้าหมายของโปรเจกต์ ก่อนที่จะนำไปสร้างเป็น Issue บน GitHub
