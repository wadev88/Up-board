# Pragmatic Promise
ผมจะรับผิดชอบงานของตัวเอง อัปเดตความคืบหน้ากับทีม และแจ้งทันทีเมื่อพบปัญหา ผมจะตรวจสอบ diff และทดสอบงานก่อนส่งให้เพื่อนร่วมทีม review

# ทำไมอยากเรียน SE
ผมอยากเรียน SE เพื่อเข้าใจกระบวนการพัฒนาซอฟต์แวร์ที่เป็นระบบ ตั้งแต่การวิเคราะห์ความต้องการจนถึงการทดสอบและดูแลระบบ ผมอยากพัฒนาทักษะการทำงานเป็นทีมและสร้างซอฟต์แวร์ที่มีคุณภาพ ดูแลต่อได้ และตอบโจทย์ผู้ใช้

# Broken Window ที่เคยเจอ
* **(1) Window คืออะไร:** ในโปรเจกต์ต้นแบบ ผมเคยปล่อย warnings และโค้ดซ้ำหรือ hardcode เพื่อรีบส่งงาน สิ่งเหล่านี้เป็นสัญญาณว่าโค้ดยังไม่ได้รับการดูแล
* **(2) ผลกระทบ:** เมื่อระบบใหญ่ขึ้น การแก้โค้ดซ้ำต้องแก้หลายจุด และ warnings ที่สะสมทำให้หาบั๊กใหม่ได้ยาก
* **(3) ถ้าแก้ทันทีจะป้องกันอะไร:** การแก้ warnings และปรับโค้ดตั้งแต่แรกจะลดโอกาสเกิดบั๊ก ลดเวลาแก้ไขในอนาคต และป้องกันไม่ให้ทีมเคยชินกับโค้ดคุณภาพต่ำ
